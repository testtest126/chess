§ 1 — the tournament math

The one model here that isn't a guess.

Every push/fold and opening range in this tool is someone's careful estimate. ICM is the one exception — a specific, computable number, once the stacks and payouts are fixed.

Tournament chips aren't worth cash 1:1 once there's a payout structure on the table, and the Independent Chip Model — the Malmuth‑Harville method, the same algorithm every ICM tool in the industry implements — converts a set of stacks into each player's exact tournament $EV. It's David Harville's 1973 method for predicting horse‑race finishing order, stack size standing in for horse strength, adapted to poker by Mason Malmuth in 1987.

Rather than trust the implementation on its own terms, the project went to Wikipedia's own ICM article, took its published three‑player worked example — a 50/30/20 chip split, a 70/30 payout — and re‑derived the exact fractions by hand from the same recursive definition the code uses, shown in the documentation so the arithmetic is checkable without running anything. The published figures (rounded, “≈$45 / $32 / $22”) and the hand‑derived exact fractions agree.

§ 2 — the honest number

Two right answers, and the tool knows which one it gave you.

“AA beats KK about 82%” is folk wisdom. Getting the actual number right meant noticing that folk wisdom is quietly averaging over a detail most people never think to ask about.

01

Which suits, exactly?

EquityTests.swift · combo‑weighted vs. exact enumeration

The combo‑weighted figure, matching cardfight.com's published table across every suit combination, is AA 81.71% / KK 17.82%. A single specific suit assignment — the exact enumeration test, all 1,712,304 possible boards, zero sampling error — lands at 82.36%, closer to the number poker folklore usually quotes. Both are correct; they're answers to two subtly different questions, and the test suite is explicit, in a code comment, about which one it's asserting and why.

“About 82%” is two different exact numbers wearing one rounding. Know which one you're citing.
02

The bounty that says when it doesn't apply

BountyEquity.swift · PKO bounty math

A bounty widens the shove range — but only when the hero actually covers the villain's stack, only in the direction a hand can be pulled into the range, never out of it. The tool's own reasoning string says so out loud when it doesn't apply: “a bounty is on the table, but hero doesn't cover villain here, so it isn't collectible on this shove — no adjustment applied.” A tool that only ever tells you when a number changed, and stays silent about the times it didn't, is halfway to overclaiming.

Say the adjustment didn't apply, in exactly as many words as you'd use to say it did.

§ 3 — proven

Not confident. Checked.

Every other range in this tool is a percentage someone had to estimate, and the tool says so plainly rather than dressing an estimate up as exact math. ICM is the one place the codebase gets to be certain — and it earned that certainty the only honest way available: by finding someone else's published answer first, and refusing to ship until its own arithmetic matched it, in public, showing the work.

That's what “proven” means here. Not a confident tone. A number somebody else already checked, checked again.
