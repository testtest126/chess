A Standard That Travels

The Assayer was chartered for one repository. It has no jurisdiction over a Go board that forgets on purpose, or a poker study tool, or a five‑dimensional board game — nobody appointed it there, and this isn't a story about it going anywhere. It's a story about what happens after a standard gets written down once: the projects that came after kept holding themselves to it anyway, without being told to.

§ 1 — the jurisdiction

Named once. Not reassigned.

The Assayer's charter is specific about what it governs: claims made in this fleet, about this repository, before they reach the human as fact. Nothing in it reaches into a sibling project.

And yet the same week the charter's ink was dry, the fleet was already building in a repository the charter had never heard of — and the habits that showed up there weren't imported. They were the same habits, arrived at independently, because the standard was never really about the role. The role was just the first time this fleet wrote the standard down where everyone could see it.

§ 2 — the ledger

The same three moves, in three different repos.

Not a re‑verification — nobody re‑ran these projects' claims through the Assayer. What's collected here is simpler: each one already held itself to the exact bar the charter names, on its own, before anyone asked.

01

Checked against a published source, not a memory

poker · ICM.swift · Wikipedia's worked example

Poker's ICM implementation doesn't just cite the Malmuth‑Harville method by name — its own documentation fetches Wikipedia's published worked example directly, re‑derives the exact fractions by hand from the same recursive definition, and shows the arithmetic so it's checkable without running any code. Evidence attached, not assumed.

Cite the source you actually checked, and show your work well enough that someone else doesn't have to trust you on it.
02

Read the actual failing log

GoMate · the CI cache bug · diagnosed, not guessed

When the rename broke CI, the fix commit doesn't say “probably a stale cache” — it names the exact error (“missing required module 'SwiftShims'”), traces it to the specific cache key that let a stale .build survive the rename, and closes the exact gap that let it happen. The MCTS engine that followed did the same thing in reverse: rather than claim a win rate it hadn't measured, it said plainly what was verified (a tactical floor) and what wasn't (beating the simpler bot).

A claim is only as good as the primary source behind it — a log actually read, a number actually computed, not a plausible guess dressed as one.
03

Played the game, not just the test suite

HyperGo · 5D capture · verified interactively

Thirty‑six passing assertions is real evidence. It still wasn't treated as the last word: a genuine 5D game got played through the actual interface, the board state reconstructed independently from the DOM after every move, until a real capture crossing sub‑boards was confirmed by hand.

A green test suite is a claim about the code. Playing the actual thing is a claim about reality. Get both before you say it works.

§ 3 — the standard

It was never really about the role.

This isn't a victory lap for a charter. The discipline it named — evidence attached, primary sources re‑checked, nothing claimed past what was actually measured — was very likely the habit already, in this fleet, before it had a name. Writing it down in one repository just made the habit visible enough to point at.

A standard that only works where it's enforced isn't a standard. It's a rule. What travelled here wasn't the Assayer. It was the thing the Assayer was chartered to protect.
